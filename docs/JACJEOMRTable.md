## Working rules (read before taking a row)

1. **This MR works the TOOLCHAIN area of the `jac2024` folder** (`jac2024/jacBuild24/...`), not the application. PracticeForceOne (`jac2024/app/com/claimsprocessing/`) is touched only in Pillar J9 (adoption). Do not mix toolchain and app changes in one commit; never edit the legacy build trees (jacBuild8/13/23) — `jacBuild24` is the only live toolchain.
2. **Hot files (serialize via AGENTS.md claim):** `jacBuild24/source/scripts/com/esarks/jac/generators/GenerateService.script` (the catch-template owner), `GenerateJeo.script`, `jacBuild24/source/scripts/com/esarks/arm/model/jeo/ServiceJeo.script`. One owner at a time per file.
3. **Gate zero:** NO generator/template edit may land before J0.1 (golden harness) is Done. The golden diff is this MR's equivalent of the A0 characterization gate.
4. **Evidence bar:** a row is Done only with (a) golden-diff or behavioral-test proof in `jacBuild24/test/` output, (b) for anything reaching PFO: `phase-generate` + `phase-compile-data` + `compile-router` green and the 141-scenario characterization gate green before/after. "Compiles" is not proof.
5. **Back-compat is a hard requirement:** every change must leave LEGACY mode byte-equivalent to today's behavior. The reply envelope keeps receiving errors in all modes.
6. **Sanitization rule:** no exception message, log line, or HTTP body may carry SQL text or bound values — location + title + SQLState + vendor first-line only.
7. Cross-agent channel: AGENTS.md. Per-row claims, evidence, and hand-offs are posted there; this table holds durable status.
