# GenerateDdl - Database DDL Generation

## Purpose

GenerateDdl is a JAC generator that creates Data Definition Language (DDL) scripts for relational databases. It generates CREATE TABLE, CREATE VIEW, and related database schema statements from XML definitions, supporting multiple database platforms (SQL Server, MySQL, PostgreSQL).

## Input XML Schema

### Schema Definition
- **Root element**: `<com.esarks.arm.schemas.ddl.root>`
- **Schema namespace**: `com.esarks.arm.schemas.ddl.root`

### Table Definitions

```xml
<com.esarks.arm.schemas.ddl.root>
<tables>
  <table name="FAMILIES">
    <field name="FAMILY_ID" type="string" size="36" nullable="false" />
    <field name="OWNER_ID" type="string" size="255" />
    <field name="FAMILY_NAME" type="string" size="255" />
    <field name="CREATED_AT" type="timestamp" />

    <primary>
      <field>FAMILY_ID</field>
    </primary>

    <unique name="UK_FAMILIES_OWNER">
      <field>OWNER_ID</field>
    </unique>

    <foreign name="FK_FAMILIES_USER" table="USERS">
      <field from="OWNER_ID" to="USER_ID"/>
    </foreign>

    <index name="IDX_FAMILIES_NAME">
      <field>FAMILY_NAME</field>
    </index>
  </table>
</tables>
</com.esarks.arm.schemas.ddl.root>
```

### Field Types
- `string` - VARCHAR/NVARCHAR with `size` attribute
- `integer` - INT/INTEGER
- `decimal` - DECIMAL with optional `precision` and `scale` attributes
- `timestamp` - DATETIME/TIMESTAMP
- `date` - DATE
- `time` - TIME
- `boolean` - BIT/BOOLEAN
- `text` - TEXT/NTEXT/CLOB for large text fields

### Field Attributes
- `name` - Column name (SCREAMING_SNAKE_CASE by convention)
- `type` - Data type (see Field Types above)
- `size` - Length for string types
- `precision`, `scale` - For decimal types
- `nullable` - "true" or "false" (default: true)
- `identity` - "true" for auto-increment columns (database-specific handling)
- `default` - Default value

### Constraint Elements
- `<primary>` - Primary key constraint
- `<unique>` - Unique constraint with `name` attribute
- `<foreign>` - Foreign key with `name` and `table` attributes
- `<index>` - Index definition with `name` attribute

### View Definitions

```xml
<com.esarks.arm.schemas.ddl.root>
<views>
  <view name="ACTIVE_FAMILIES_VIEW">
    <select>
      SELECT FAMILY_ID, FAMILY_NAME, CREATED_AT
      FROM FAMILIES
      WHERE STATUS = 'ACTIVE'
    </select>
  </view>

  <!-- OR declarative style -->
  <view name="FAMILY_SUMMARY">
    <table name="FAMILIES" alias="f"/>
    <column name="FAMILY_ID"/>
    <column name="FAMILY_NAME"/>
    <column name="MEMBER_COUNT" expression="COUNT(*)"/>
    <join table="FAMILY_MEMBERS" alias="m" on="f.FAMILY_ID = m.FAMILY_ID"/>
    <where>f.STATUS = 'ACTIVE'</where>
    <groupBy>f.FAMILY_ID, f.FAMILY_NAME</groupBy>
    <order>f.FAMILY_NAME ASC</order>
  </view>
</views>
</com.esarks.arm.schemas.ddl.root>
```

## Output Artifacts

### Generated Files

1. **`{PackageName}.{TableName}.sql`** - DDL script file
   - CREATE TABLE or CREATE VIEW statement
   - DROP TABLE/VIEW IF EXISTS (for clean regeneration)
   - All constraints (PK, FK, unique, indexes)
   - Database-specific syntax adaptations

2. **`{PackageName}.{TableName}.html`** - Documentation file
   - Table/view structure documentation
   - Field descriptions
   - Constraint relationships
   - Visual schema representation

### Example Output (SQL Server)

```sql
-- Generated by Architect's Companion - GenerateDdl
-- Table: FAMILIES

IF OBJECT_ID('dbo.FAMILIES', 'U') IS NOT NULL
    DROP TABLE dbo.FAMILIES
GO

CREATE TABLE dbo.FAMILIES (
    FAMILY_ID NVARCHAR(36) NOT NULL,
    OWNER_ID NVARCHAR(255) NULL,
    FAMILY_NAME NVARCHAR(255) NULL,
    CREATED_AT DATETIME NULL,

    CONSTRAINT PK_FAMILIES PRIMARY KEY (FAMILY_ID),
    CONSTRAINT UK_FAMILIES_OWNER UNIQUE (OWNER_ID)
)
GO

CREATE INDEX IDX_FAMILIES_NAME ON dbo.FAMILIES (FAMILY_NAME)
GO

ALTER TABLE dbo.FAMILIES
    ADD CONSTRAINT FK_FAMILIES_USER
    FOREIGN KEY (OWNER_ID) REFERENCES dbo.USERS (USER_ID)
GO
```

## Key Features

### Multi-Database Support
- **SQL Server**: NVARCHAR, DATETIME, IDENTITY(1,1), dbo schema prefix
- **MySQL**: VARCHAR, DATETIME, AUTO_INCREMENT, backtick quoting
- **PostgreSQL**: VARCHAR, TIMESTAMP, SERIAL, double-quote quoting

The generator detects the target database from context properties and adapts:
- Data type mappings
- Identity/auto-increment syntax
- Schema/catalog prefixes
- Quoting conventions
- DROP IF EXISTS syntax

### Database-Specific Adaptations

```java
// Identity column handling
if (database.equals("sqlserver")) {
    // IDENTITY(1,1)
} else if (database.equals("mysql")) {
    // AUTO_INCREMENT
} else if (database.equals("postgresql")) {
    // SERIAL
}
```

### Token Replacement
Supports variable substitution in SQL:
- `$TableName` - Replaced with actual table name
- `$DatabasePrefix` - Schema/database prefix
- Custom tokens from properties

### Direct Execution
Can execute DDL directly via JDBC:
```java
performSqlFile("com/esarks/examples/tables/Families.sql");
performSqlStatement("CREATE TABLE ...");
```

## Generated Methods

GenerateDdl creates Java classes with these methods:

### Table Operations
- **`createTable(String xmlDef, String tableName, Boolean force)`**
  - Generates and optionally executes CREATE TABLE DDL
  - `force=true` regenerates even if file exists

- **`dropTable(String xmlDef, String tableName)`**
  - Generates DROP TABLE DDL

- **`loadTable(String xmlDef, String tableName)`**
  - Loads test data into table from XML

### View Operations
- **`createView(String xmlDef, String viewName)`**
  - Generates CREATE VIEW DDL

- **`dropView(String xmlDef, String viewName)`**
  - Generates DROP VIEW DDL

### Execution Methods
- **`performSqlFile(String sqlFilePath)`**
  - Executes SQL file via JDBC
  - Logs results to console

- **`performSqlStatement(String sql)`**
  - Executes single SQL statement
  - Returns row count for DML

## Configuration Options

### Context Properties

```xml
<properties>
  <property name="database" value="sqlserver"/>  <!-- mysql, postgresql -->
  <property name="databasePrefix" value="dbo."/> <!-- Schema prefix -->
  <property name="jdbcUrl" value="jdbc:sqlserver://localhost:1433;databaseName=AllowanceAlley"/>
  <property name="jdbcUser" value="sa"/>
  <property name="jdbcPassword" value="password"/>
</properties>
```

### Generator Parameters
- **`force`**: Boolean - Regenerate even if file exists
- **`execute`**: Boolean - Execute DDL after generation
- **`drop`**: Boolean - Include DROP statements

## Usage Example

### In GenerateComponents.xml

```xml
<component type="SqlTable"
           name="Families"
           source="app/com/esarks/examples/generateDdl/FamiliesSqlTable.xml"/>
```

### Standalone Execution

```java
// In .jrun or test file
GenerateDdl lGen = new GenerateDdl();
lGen.createTable("app/com/esarks/examples/generateDdl/FamiliesSqlTable.xml",
                 "Families",
                 true); // force regeneration

// Execute the generated DDL
lGen.performSqlFile("com/esarks/examples/tables/Families.sql");
```

### From RunMakeAll
The generator is typically invoked as part of a complete build:
```
RunMakeAll.jrun
  → Reads GenerateComponents.xml
  → Finds SqlTable components
  → Invokes GenerateDdl for each
  → Creates .sql files in output directory
```

## Best Practices

1. **Naming Conventions**: Use SCREAMING_SNAKE_CASE for database identifiers
2. **Primary Keys**: Always define primary keys for tables
3. **Foreign Keys**: Document relationships with FK constraints
4. **Indexes**: Add indexes for frequently queried columns
5. **Nullable Flags**: Explicitly set `nullable="false"` for required fields
6. **Size Limits**: Specify appropriate `size` for VARCHAR columns
7. **Identity Columns**: Use for surrogate keys, typically on primary keys

## Common Patterns

### Complete Table with All Features
```xml
<table name="CHORE_ASSIGNMENTS">
  <!-- Fields -->
  <field name="ASSIGNMENT_ID" type="string" size="36" nullable="false" identity="true"/>
  <field name="FAMILY_ID" type="string" size="36" nullable="false"/>
  <field name="CHORE_ID" type="string" size="36" nullable="false"/>
  <field name="MEMBER_ID" type="string" size="36" nullable="false"/>
  <field name="DUE_DATE" type="date" nullable="false"/>
  <field name="POINTS" type="integer" default="0"/>
  <field name="STATUS" type="string" size="50" default="'PENDING'"/>
  <field name="CREATED_AT" type="timestamp" default="GETDATE()"/>

  <!-- Primary Key -->
  <primary>
    <field>ASSIGNMENT_ID</field>
  </primary>

  <!-- Foreign Keys -->
  <foreign name="FK_ASSIGNMENTS_FAMILY" table="FAMILIES">
    <field from="FAMILY_ID" to="FAMILY_ID"/>
  </foreign>
  <foreign name="FK_ASSIGNMENTS_CHORE" table="CHORES">
    <field from="CHORE_ID" to="CHORE_ID"/>
  </foreign>
  <foreign name="FK_ASSIGNMENTS_MEMBER" table="FAMILY_MEMBERS">
    <field from="MEMBER_ID" to="MEMBER_ID"/>
  </foreign>

  <!-- Indexes -->
  <index name="IDX_ASSIGNMENTS_FAMILY">
    <field>FAMILY_ID</field>
  </index>
  <index name="IDX_ASSIGNMENTS_DUE">
    <field>DUE_DATE</field>
  </index>
  <index name="IDX_ASSIGNMENTS_STATUS">
    <field>STATUS</field>
  </index>

  <!-- Composite Unique Constraint -->
  <unique name="UK_ASSIGNMENTS_UNIQUE">
    <field>FAMILY_ID</field>
    <field>CHORE_ID</field>
    <field>DUE_DATE</field>
  </unique>
</table>
```

This generator forms the foundation of the JAC data layer, ensuring consistent, portable database schema generation across multiple database platforms.
